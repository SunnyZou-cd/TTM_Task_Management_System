# TTM Task Management System

应用名称：**Pinboard**。Windows 任务管理与桌面悬浮便笺应用。

Windows 桌面应用。主窗口管理任务和便笺，重要内容可以固定为其他应用上方的独立窗口。

## 先运行

1. 在仓库 Releases 下载 `Pinboard-0.1.0-Windows.exe`，双击打开；自行构建时文件位于 `release` 目录。这是免安装版，会解压运行时并在本机保存数据。未购买代码签名证书，Windows 可能显示“未知发布者”；仅运行你信任的本项目构建。**成功标志：看到“我的任务”，初始列表为空。**
2. 点击“新建任务”，填写标题和可选截止日期，保存。**成功标志：任务出现在列表中，点击圆形按钮可以完成或恢复。**
3. 点击任务旁的图钉。拖动便笺上方工具栏，拖动窗口边缘调整大小。**成功标志：出现独立便笺，切换到其他普通应用时仍可见；图钉可以关闭或重新开启置顶。**
4. 在便笺直接修改内容。关闭便笺只取消固定，不删除条目。关闭主窗口后，已固定便笺继续运行；托盘菜单可以重新打开主窗口或退出。**成功标志：主列表和便笺内容一致，退出再打开后内容与固定便笺恢复。**

## 云端账号

邮箱验证码登录和 Supabase 同步代码已实现，但需要你自己的 Supabase 项目。未配置时仍可在本机使用，并明确显示“未配置云端”。

请按 [云端配置指南](docs/CLOUD_SETUP.md) 建立数据库、开启邮箱验证码模板，然后在“账号与设置”填写项目 URL 和客户端公开密钥。**不要填写数据库密码、secret key 或 service_role key。**

登录后的账号工作区与登录前的本机工作区分开；本机内容不会自动上传。退出登录可以回到本机工作区。离线更改留在本机，登录状态下每 30 秒尝试同步，也可以点击“立即同步”。置顶状态和窗口位置只存在本机。云端服务可能产生费用；首次配置前检查你选用的服务配额。

**尚待真实服务验收：邮件投递、SQL 执行、跨设备同步与线上账号隔离。** 已通过的模拟测试不能替代这一步。

## 开发运行

以下命令的作用是进入项目、安装所需工具、启动开发版。`npm ci` 会联网下载依赖，并写入本项目的 `node_modules`；不改其他项目。需要 Node.js 24。

1. 打开 PowerShell，执行：

   ```powershell
   git clone https://github.com/SunnyZou-cd/TTM_Task_Management_System.git
   Set-Location '.\TTM_Task_Management_System'
   npm ci
   ```

   **成功标志：安装结束，没有报错。**

2. 启动开发版：

   ```powershell
   npm run dev
   ```

   **成功标志：弹出 Pinboard 窗口。** 开发版主进程修改需要退出后重启；界面修改自动刷新。

3. 验证功能与生成程序：

   ```powershell
   npm test
   npm run test:desktop
   npm run dist
   ```

   **成功标志：数据测试通过、两轮桌面验收通过，`release` 内生成 Windows EXE。** 桌面验收用 `work` 下的独立数据目录与隐藏窗口，测试数据不写入正式工作区。

## 数据与恢复

- 正式数据保存到 Windows 用户应用数据目录。打包版通常在 `%APPDATA%\Pinboard`，开发版通常在 `%APPDATA%\pinboard-desktop`。精确目录取决于 Electron 的应用名称。
- `database.json` 保存本机与账号缓存；`window-bounds.json` 保存便笺位置；`session.enc` 使用 Windows 安全存储加密登录凭据。
- “导出备份”导出当前工作区可见条目的 JSON，不包含登录令牌；v0.1 尚无自动导入入口。完整本机备份可以在退出应用后复制整个数据目录。恢复时先保留现有目录，再将同版本备份放回原位置；加密凭据不保证可迁移到其他 Windows 用户，必要时重新登录。
- 如果数据文件损坏，应用停止启动并保留文件，避免用空数据覆盖。请先备份再修复，不要直接删除唯一副本。

## 当前边界

- 技术栈：Electron、React、TypeScript、Supabase。交互和功能保持简洁，但 Electron 随附浏览器运行时，安装包和内存体积并非原生便笺级别。
- 不含通知提醒、协作、开机启动、移动端及自动升级。截止日期只用于展示和筛选。
- 冲突按整条记录更新时间与设备 ID 处理；不提供逐字段合并。保持设备系统时间准确。
- 退出或正常关闭便笺前会等待草稿保存。强制结束进程、断电或系统强制关机仍可能丢失尚未提交的输入。
- 运行时依赖检查无已知漏洞；打包工具依赖链仍报告 8 项中等风险，集中于 `sprintf-js` 拒绝服务公告，未包含在应用运行时。避免对不可信来源执行构建。

进一步技术信息见 [架构与验证](docs/ARCHITECTURE.md)。

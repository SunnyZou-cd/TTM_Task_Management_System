# Obsidian 导入与完成状态写回

此功能访问你选中的本机文件夹。导入内容进入当前工作区：云账号工作区的内容会参与云端同步。请先核对页面显示的目标工作区。测试仅使用独立临时目录。

1. 打开侧栏 **Obsidian → 选择文件夹并预览**，选择 vault 或较小子文件夹。**成功标志：显示文件夹名称、Markdown 数量、任务数量及跳过提示。**
2. 点击 **导入到当前工作区**。每份 Markdown 保留为一条正文便笺，普通 `- [ ]` / `- [x]` 任务另列为任务；代码块和 YAML 头部中的内容不作任务。**成功标志：操作结果显示导入数，任务与便笺列表出现对应内容。**
3. 在 Pinboard 中勾选任务后，回到 Obsidian 页面点击 **备份并写回完成状态**。**成功标志：原 Markdown 对应方括号里的字符改变，文件同目录的隐藏文件夹 `.pinboard-backups` 留有原始备份。**
4. 若显示冲突，原文件不会被覆盖。**成功标志：结果指出具体文件，Obsidian 中新增的内容仍保留。** 请在 Obsidian 手动核对并勾选；当前版本没有自动合并或重新建立冲突基线的界面。

## 限制与恢复

- 不是全文双向同步，也没有后台监听；只按需将已关联任务的完成状态写回。Pinboard 标题、正文和截止日期不会写回。
- 重复导入跳过已有记录；源文件后续改动不自动覆盖已导入内容。原文件移动或改名后关联不能自动迁移。
- 仅 UTF-8 Markdown，保留 BOM、CRLF 与正文；跳过隐藏目录和符号链接。每次最多 500 文件、3000 任务，单文件 100 KB，总计 5 MB。
- 写回前核对文件哈希、先保存备份，再检查并替换原件。编辑器同时写文件仍存在极短竞争窗口；操作时避免同时保存同一文件。
- 本机 `obsidian-links.json` 保存关联和绝对路径，不上传云端。请和 `database.json` 一起备份。导入条目与关联存储不是跨文件事务，极端磁盘故障可能留下未关联条目；先保留数据再排查。
- 恢复某份 Markdown 时，先关闭正在编辑它的程序，保留当前文件，再从 `.pinboard-backups` 找到所需版本复制恢复。**成功标志：原文与所选备份一致。**

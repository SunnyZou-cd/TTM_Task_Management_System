# 架构与验证

## 数据和窗口

所有窗口通过受限的 preload API 调用同一个主进程 `AppService`。主进程序列化变更、原子写入 JSON 后广播快照，前端不会直接访问文件或操作系统。每条记录有 `task` 或 `note` 类型；两者都可固定为窗口，任务便笺还可以勾选完成。

`WindowManager` 管理主窗口、独立便笺和托盘。便笺默认启用 Windows always-on-top，可拖动和缩放。正常关闭先向便笺请求保存确认，再取消固定；退出应用时先收集所有便笺的保存结果，成功才退出，并保留固定记录。窗口位置本机存储，恢复时限制在当前屏幕范围内。

## 安全边界

- renderer 启用沙盒和 context isolation，禁用 Node 集成。
- IPC 只公开具名方法，并核对调用窗口、主框架和本机页面地址；拒绝外部导航、新窗口和 webview。
- 登录令牌通过 Electron safeStorage 使用 Windows 凭据保护机制加密，无法加密时拒绝明文存储。
- 客户端只接受 Supabase publishable/anon 公开密钥，数据库采用 RLS 和 `auth.uid()` 检查。
- SQL 同步函数采用调用者权限，旧版本记录不能覆盖服务器上更新的版本。
- CSV/HTML 等外部内容不执行；便笺正文由 React 按文本渲染。

## 同步

本机访客、不同账号和不同 Supabase 项目分开缓存。登录不会自动将访客内容关联到账号。记录包含更新时间、设备 ID 和删除墓碑。修改先持久化到本机待同步集合，然后上传并分页下载云端数据；只有整个流程成功才显示已同步。单次网络请求有 15 秒超时。

v0.1 同步和编辑通过同一串行队列避免覆盖正在保存的内容。在网络较慢或待同步条目很多时，编辑提交可能等待当前同步完成。上传按记录进行，下一版可以改为批量上传并拆分网络和磁盘队列。多设备冲突采用整条记录的最后写入策略，设备时间会影响结果。

## 验证证据

`npm test` 的 11 项模拟测试覆盖离线重启、访客和账号隔离、不同后端项目隔离、同步期间编辑、删除墓碑、存储损坏、写入失败、密钥类型与合法日期。

`npm run test:desktop` 启动真实 Electron 隐藏窗口，用独立数据目录验证界面创建任务、完成状态、置顶切换、缩放、跨窗口更新、原生关闭保存、主窗口关闭后便笺继续工作、退出保存、重启恢复、屏幕外位置修正及删除关闭便笺，并生成截图。

隐藏窗口测试核对 Electron 原生置顶属性；实际与其他软件并排使用仍应由用户做短验收。没有真实 Supabase 项目时，不声称通过线上数据库、邮件或跨设备验证。

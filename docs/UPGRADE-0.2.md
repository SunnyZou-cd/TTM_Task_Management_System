# 0.2 升级说明

## 技术栈确认

沿用 Electron 44.7.2、React 19.3、TypeScript、Vite 8.3.4 和 Supabase JS 2.117.3。Electron 主进程负责文件和窗口，React 页面通过限定的 preload API 操作数据；本地 JSON 原子写入，云端配置和账号隔离保持原有设计。

本次不迁移桌面框架。首先定位启动路径中的实际耗时，再消除可避免的等待。[Electron 官方性能指南](https://www.electronjs.org/docs/latest/tutorial/performance) 同样建议先测量，再推迟非必要初始化与网络请求。

## 需求来源与范围

用户截图要求管理界面增加 Dashboard、日历、进度追踪、Obsidian import/sync；便笺支持主题适配、去掉 Windows 导航栏以及悬停缩放。引用聊天可读取的用户消息明确要求：悬浮后尽量减小面积，同时保留内容。

管理视图使用现有任务数据，不伪造历史趋势：概览显示当前工作区状态，日历按截止日期分组，进度显示当前任务的完成比例。便笺继续使用 Electron 无边框窗口，保留键盘可达的关闭、返回和置顶操作。

## 验证边界

性能数据以同机、独立空数据目录、进程启动至标题及数据接口可用为口径。它不等同于所有电脑的冷启动表现。安装包首次安装需要解压，安装后的日常启动不再执行便携包的解压流程。

Obsidian 验收使用专用临时测试目录，不读取用户真实笔记库。云端登录与跨设备同步仍需用户配置真实 Supabase 服务后验收。

## 本机实测与交付验证

2026-10-14，空测试工作区：旧 0.1 便携 EXE 首轮 24797ms、复测 10044ms；新版 0.2 已解压程序 890ms、868ms。测试含浏览器页面标题与 preload 数据读取成功；系统缓存、实时扫描与机器负载会影响结果。安装包生成成功，程序的已解压发行目录通过启动与磁盘保存验收；没有在用户系统实际运行安装向导。

首屏读取本机缓存后打开，云端身份验证在后台执行。同步网络请求移出编辑队列，只在短事务中合并返回数据；网络期间的新编辑保持待同步，不会被旧上传结果清掉。

通过：24 项单测、原桌面创建/重启两轮、管理页概览与实时进度/月历预填/跨窗口主题、悬停收起展开、原生窗口完整尺寸持久化、真实 Electron Obsidian IPC 的预览/重复导入/备份写回/冲突阻止。机械界面检测结果为空；独立视觉审查在提供的任务、展开便笺及深色月历截图范围内给出 ship。

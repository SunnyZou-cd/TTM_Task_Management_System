# 课程版本：建议的阅读顺序

目标是能解释并独立修改代码。核心知识是函数、类、列表/字典、排序、贪心、区间和文件操作；不以“看起来像谁写的”作为代码正确性的判断。

## 1. 先看数据

程序只保存一个普通字典：tasks是任务列表，busy是忙碌时段，locks是固定安排，plan是生成结果，settings是策略和块长设置。每条任务也是字典，不需要先学习模型协议或dataclasses。

时间用“从1970年起经过多少分钟”的整数保存。这样区间比较就是整数比较，时长就是end-start；输入/显示才用datetime转换成本机年月日时分。剩余分钟表示实际未完成工作，生成计划不减少它。

## 2. 再看scheduler.py

算法主线：

```text
检查任务和锁定是否合理
从当前时间到规划结束建立空闲区间
扣除忙碌时段和锁定块
对每个任务：待安排 = 剩余分钟 - 已锁定分钟
循环：
    按选中的策略排序任务
    找第一个还能安排的任务
    在最早合法空档放一块，再从空档扣除它
    如果所有任务都放不下，结束
统计未排分钟和计划覆盖情况
```

EDF按截止时间排序；Importance先按重要性降序；Risk根据截止接近程度、重要性、剩余工作/剩余容量评分。Risk每次分配后重新计算，是贪心启发式，不保证最优。

### 一组可手算的例子

规划09:00–11:00，09:30–10:00忙碌。A需要45分钟、10:30截止、重要性3；B需要30分钟、11:00截止、重要性5；块长15–60分钟。

EDF先安排A：09:00–09:30加10:00–10:15；再安排B：10:15–10:45，两个任务都排满。

Importance先安排B：09:00–09:30；A只能安排10:00–10:30，留下15分钟。策略只是决定“先给谁”，同一个区间分配器负责不重叠、不超截止等约束。

分析复杂度时，先数任务候选的排序次数和每次遍历的空档数，而不是笼统地说“算法是O(n log n)”；多轮分配会重复排序。

## 3. 然后看storage.py

load是打开文件→解析JSON→检查数据；save是检查外部修改→保留旧文件.bak→写临时文件→替换。函数输入输出直接可见，没有Store类或提交协议。

import_legacy只把旧工作区转换为新的列表/字典，导入后另存新文件，原文件不修改。它是迁移工具，不属于调度算法。

## 4. 最后看ui.py

只有一个主要的PlannerApp类。self.data就是当前数据；按钮command直接对应新增、编辑、完成、生成、保存等方法。Canvas负责画日历，点击坐标换算为日期和分钟。刷新界面不代表重新计算或完成任务。

先从启动和生成按钮往下读，再看任务表单、日历点击和存档。语言文字使用直接映射，避免运行时遍历界面猜测要翻译什么。

# Demo 1 Tkinter GUI 计划 · 2026-11-16

## 目标

将 Demo 1 的实际任务工作区做成 Python 自带 Tkinter 的桌面窗口。默认执行 `python demo1.py` 打开 GUI；`--terminal` 继续提供原终端菜单，`--demo` 显式运行合成案例。用户可从表单完成任务管理、时间设置、调度、锁定和本地存档操作，无需编辑 JSON，也无需安装项目包。

界面默认 English，语言选择器提供 English 和简体中文。GUI 复用已实现的 Workspace / Store 和调度核心，不创建另一份状态模型。默认存档路径保持 `work/demo1-data/workspace.json`；数据只留在本机，不连接真实任务数据库、外部账号或 Electron。

## 主窗口结构

窗口顶部保留存档操作按钮和当前存档、dirty（未保存）状态、时区信息。主要工作区划分为三个页签：

| 页面 | 英文标签 | 主要操作 |
| --- | --- | --- |
| 任务 | `Tasks` | 查看任务；填写 Title、Total minutes、Remaining minutes、Priority 1–5、Earliest start、Deadline 和 Allow splitting；新增、修改、记录剩余分钟、标记完成、删除 |
| 时间 | `Time` | 设置 IANA 时区和规划窗口；列出、添加、删除可用时段与忙碌时段 |
| 计划 | `Plan` | 选择 EDF / importance / risk，设置最小/最大块长；生成/重排、比较三策略、查看时间块和未排原因、锁定/解锁计划块 |

顶部存档操作：`Save` 保存当前路径，`Save as` 另存为新路径，`Open workspace` 选择一个已存在的工作区文件，`Reload` 从当前路径重新加载。语言控件为 `Language / 语言`，选项是 `English` 和 `简体中文`，默认 English。语言切换仅在本次窗口会话生效，不写入个人存档。

## 使用流程

1. **启动：** `python demo1.py` 默认创建未保存的空白 Workspace；若默认存档存在则校验并载入，不运行预设案例。窗口状态显示路径、时区和是否有未保存修改。
2. **管理任务：** 用户在 Tasks 页管理完整任务字段。操作先通过 Workspace 事务验证，成功后更新视图并标记 dirty；失败的表单操作不提交半成品。
3. **配置时间：** 在 Time 页设置工作区时区、规划窗口和可用/忙碌区间。默认 UTC；本地时间按 `YYYY-MM-DD HH:MM` 解析。不存在的 DST 时间拒绝，重复 DST 时间要求显式偏移。使用其他 IANA 时区时，系统缺少时区库则提示安装 `tzdata`。
4. **生成与查看：** 在 Plan 页选择策略与块长后生成计划。结果需显示任务标题、时间区间、分钟、锁定状态、未排分钟及中文原因。生成结果是安排，不会自动减少剩余分钟或改成完成状态。
5. **比较：** 同一份当前工作区输入分别计算三种策略；比较结果独立窗口展示，不更改当前策略、结果或 dirty 状态。
6. **锁定与重排：** 只能从当前有效计划选择尚未开始的块锁定。编辑数据使旧结果失效；后续重排保留有效锁定块，只替换自动安排部分。已开始或已过去的锁定块阻止自动重排；用户先解锁并按实际进度修改剩余分钟，不将经过时间作为完成证据。
7. **保存与恢复：** Save 通过原子替换保存当前工作区。覆盖已有文件前生成 `.bak`；存档加载和写入验证结构、当前结果和并发 SHA256。检测到外部修改、损坏或错误文件时明确报错且不覆盖。Save as 使用新路径；已有目标拒绝覆盖。保存失败保留当前内存状态。
8. **关闭与重载：** dirty 状态下关闭、Reload 或 Open workspace 前要求用户选择保存/放弃/取消。取消继续留在当前界面；放弃只丢弃未保存内存修改。加载失败时继续保留当前 Workspace。

## 命令模式

- `python demo1.py`：默认图形界面。
- `python demo1.py --data PATH`：GUI 使用指定的个人工作区存档。
- `python demo1.py --terminal [--data PATH]`：原终端菜单。
- `python demo1.py --demo`：仅运行可行、超载和锁定重排的合成案例。
- 原 JSON 子命令 `schedule`、`compare`、`validate` 和演示过滤参数继续保留。

GUI 不启动外部进程、不调用浏览器、不连接数据库。默认关闭存档文件外的持久化；`work/` 下的测试和演示输出不提交。

## 验收要求

GUI 验收必须用真实 Tk 主循环/窗口事件完成，而不能只通过 Workspace API 替代。覆盖首次空白启动、默认 English 与语言切换、任务 CRUD 和进度、时区/availability/busy、策略与生成、结果显示、比较不改当前结果、锁定及重排、保存/另存/打开/重载、dirty 保护、损坏/并发文件冲突、窗口关闭行为。无桌面环境的自动化测试可使用 `tkinter` 的虚拟 display 或受控 UI 事件，但需另行记录真实 Windows 窗口是否可见和可操作。

本文件定义实现和验收范围，不是通过报告。实测结果只写入 [DEMO1_GUI_VERIFICATION.md](DEMO1_GUI_VERIFICATION.md)，并与先前已通过的终端/工作区验收分开。
